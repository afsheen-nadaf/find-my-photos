How it works behind the scenes

There are no servers to manage. Seven small Lambda functions each do one job, and AWS runs them only when something happens.

When you add a photo

  1. BrowserAsks for an upload link

    Calls POST /upload-url on API Gateway for each photo.

  2. LambdaGetUploadUrl

    Triggered by API Gateway. Returns a signed, short-lived link to a private S3 bucket.

  3. S3The photo is stored

    Your browser uploads straight to S3. The new file raises an event.

  4. LambdaIndexPhoto

    Triggered by that S3 event. Asks Rekognition to find and remember every face, then saves a record in DynamoDB.

  5. LambdaThumbnail

    Triggered by the new DynamoDB record through its stream. Saves a small preview back to S3.

  6. LambdaEmbedPhoto

    Triggered when the thumbnail is saved. Turns the photo into an embedding with Bedrock Titan and tags it with Rekognition labels.

  7. LambdaListPhotos

    Triggered by API Gateway. Gives this page the album with signed thumbnail links.

When you add a selfie

  1. BrowserSends the selfie

    Shrinks the image and calls POST /search on API Gateway.

  2. LambdaFindMyPhotos

    Triggered by API Gateway. Handles the selfie in memory only, so it is never stored.

  3. RekognitionCompares faces

    Matches your face against every face indexed from the album photos.

  4. DynamoDB and S3Looks up the matches

    FindMyPhotos fetches each matching photo's record and replies with signed, short-lived links.

When you describe a photo

  1. BrowserSends your description

    Calls POST /search-text on API Gateway.

  2. LambdaTextSearch

    Embeds the text with Bedrock Titan, compares it with every stored photo embedding, and returns the closest photos with signed links.

The seven functions

GetUploadUrlAPI Gateway: POST /upload-url
IndexPhotoS3: new file in originals/
ThumbnailDynamoDB Stream: new record
EmbedPhotoDynamoDB Stream: thumbnail saved
ListPhotosAPI Gateway: GET /photos
TextSearchAPI Gateway: POST /search-text
FindMyPhotosAPI Gateway: POST /search

Built for a serverless architecture and microservices course. Photos stay in a private S3 bucket and are shared only through short-lived signed links.
